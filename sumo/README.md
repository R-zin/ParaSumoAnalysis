# SUMO demo scenario

A small, reproducible SUMO scenario that generates real per-vehicle data for
the C++ analyzer. **SUMO is optional** — if it is not installed, the
synthetic datasets (`tools/generate_dataset.cpp`) let the entire
serial/OpenMP experiment run unchanged.

## Files

| File | Purpose |
|------|---------|
| `network.net.xml` | 3×3 signalized grid network, generated by `netgenerate` |
| `routes.rou.xml`  | vehicle demand (4 flows converging on the centre junctions) |
| `simulation.sumocfg` | runnable SUMO configuration |
| `tripinfo.xml`    | *(generated)* per-vehicle trip output |
| `fcd.xml`         | *(generated)* floating-car data |

## Quick start

The exact commands below were used on this machine. `SUMO_HOME` points at the
pip-installed `eclipse-sumo` package; adapt to your install.

```bash
# 1. install SUMO (choose one)
pip install eclipse-sumo                 # provides sumo/netgenerate/... binaries
# or: sudo apt-get install sumo sumo-tools   (Debian/Ubuntu)
# or build from source (macOS has no Homebrew formula)

# 2. (re)generate the network — already committed, so this is optional
netgenerate --grid --grid.number=3 --grid.length=200 \
    --default.speed=13.89 --tls.guess --output-file=sumo/network.net.xml

# 3. run the simulation (writes sumo/tripinfo.xml and sumo/fcd.xml)
sumo -c sumo/simulation.sumocfg

# 4. convert SUMO output to the analyzer's CSV layout
python3 tools/sumo_tripinfo_to_csv.py sumo/tripinfo.xml data/sumo_tripdata.csv

# 5. analyze — serial and OpenMP (results must agree)
./build/traffic_analysis_serial data/sumo_tripdata.csv
./build/traffic_analysis_openmp data/sumo_tripdata.csv --threads 8 --verify
```

On this machine step 3 produces **945 completed trips** with non-trivial
waiting time (avg ≈ 9.4 s, max ≈ 1050 s), so the delay/congestion metrics
are meaningful. A sample of the generated CSV is committed as
`data/sumo_tripdata.csv`.

## How the fields map

`tools/sumo_tripinfo_to_csv.py` maps each `<tripinfo>` record:

| CSV column    | SUMO tripinfo attribute          | Notes |
|---------------|----------------------------------|-------|
| `vehicle_id`  | `id`                             |       |
| `speed`       | `routeLength / duration`         | mean trip speed, m/s |
| `travel_time` | `duration`                       | s |
| `waiting_time`| `waitingTime` (else `timeLoss`)  | s |
| `distance`    | `routeLength`                    | m |

## Scaling up

* more vehicles → lower the `period` values in `routes.rou.xml`;
* a bigger network → raise `--grid.number`;
* real demand → replace `routes.rou.xml` with `duarouter` output from an OD
  matrix, or import an OSM network with `netconvert --osm-files`.
